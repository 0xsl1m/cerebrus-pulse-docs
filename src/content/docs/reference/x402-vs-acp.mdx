# x402 vs A2A vs ACP

Cerebrus services are available through three protocols. Choose based on your use case.

## Comparison

| | x402 (Direct API) | A2A (Agent-to-Agent) | ACP (Virtuals Protocol) |
|---|---|---|---|
| **Target user** | Developers, bots, dashboards, agents | A2A agent networks | Agents on Virtuals Protocol |
| **Payment** | USDC micropayments on Base or Solana | None in-band: the reply names the HTTP endpoint and its x402 terms, and you pay there | USDC on Base, in ACP escrow |
| **Authentication** | Wallet signature (no API keys) | None: discovery and quotes are free | ACP SDK + agent wallet |
| **Discovery** | API docs | Agent Card (`.well-known`) | Virtuals marketplace |
| **Transport** | HTTP REST | JSON-RPC 2.0 over HTTP | ACP SDK |
| **Latency** | Low (~200–500ms) | Low (~200–500ms) | Higher (negotiation + escrow) |
| **Pricing** | <PriceRange /> per call | <PriceRange /> per skill (paid over HTTP) | A USDC budget per job (below) |
| **Settlement** | Instant (Base L2 or Solana) | Over HTTP (x402), as for direct calls | ACP escrow release |
| **Status** | Live | Live (discovery) | Paused |
| **Protocol** | HTTP 402 (open standard) | A2A (Linux Foundation) | Agent Commerce Protocol (Virtuals) |

## When to Use x402

- You're building a **dashboard** or **monitoring tool** that needs frequent data pulls
- You want the **lowest latency** and **lowest cost** per query
- You're writing a **bot or script** that consumes structured data
- You want to **avoid the Virtuals ecosystem** and use standard HTTP
- You need **high-frequency queries** (up to 2,000 a day per IP)

## When to Use A2A

- You're building an **AI agent** that needs to discover and consume services programmatically
- You want **standardized agent discovery** via the Agent Card protocol
- You want to ask for a skill in plain language over **JSON-RPC** (`message/send`) and be told where to get it
- You want to integrate with the **A2A ecosystem** (a Linux Foundation project)
- Your agent can then pay the named HTTP endpoint with an **x402 v2 client**

## When to Use ACP

- Your agent runs on **Virtuals Protocol** and buys services through ACP jobs and escrow
- You want the /pulse or /bundle output for one coin as an ACP deliverable
- Note: the ACP seller is **paused** while it moves to ACP v2; use x402 meanwhile

## Can I Use Multiple?

Yes. Many teams combine protocols:

1. **x402** `/pulse/BTC` → Get live technical indicators (<Price endpoint="pulse" />)
2. **A2A** `message/send` → Agent discovers a skill and gets the HTTP endpoint and x402 terms that serve it
3. **ACP** `cerebrus_synthesis` → The /bundle output for one coin, as an ACP job (when ACP is back)

A2A adds discovery on top of x402: it names the endpoint and its terms, and the payment is the same x402 call on Base or Solana. ACP sells the same engine data as ACP jobs.

## Migration

Moving between protocols doesn't require account changes. A2A leads to the same wallet-based x402 payments on Base or Solana as direct calls. ACP uses USDC on Base through Virtuals Protocol escrow. There's no lock-in to any protocol.
